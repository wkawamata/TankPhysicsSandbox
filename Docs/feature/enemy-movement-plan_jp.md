# 敵移動の段階別実装計画

更新日: 2026-10-13
状態: 合意した順序に基づく計画。未着手・実装済みを保証するチェックリストではない。

## 方針

[敵移動の仕様](enemy-movement-spec_jp.md)を小さな変更で実装する。C++20・Jolt・CMake・Visual Studio 2022の構成を維持し、ファイルはCRLFとする。
リファクタリングは機能追加と分ける。PhysicsはRenderingに依存させず、表示と可視性の情報は境界を通して渡す。数値の既定値は実装前に決定する。
リーダーの経路計算・作戦指揮への活用効果は未検証であり、検証に応じて役割を縮小・変更できる構成にする。
データ構造には最初から走行面識別と部分更新の境界を設ける。動的変化の本実装は段階5とする。

## 段階1: グループの行動制御

巡回、発見後の接近、攻撃距離での停止と条件付き射撃、見失った位置への移動、待機後の巡回復帰を実装する。
行動制御は移動目標・停止要求を生成し、走行実装から独立して試験できる構成にする。固定砲台は移動なしの既存動作を維持する。
グループ所属、指揮優先順位、作戦設定をマップデータへ追加し、旧マップの未所属ユニットは単独動作を維持する。
情報共有とグループ側の状態保持、リーダーによる移動・攻撃指示、破壊時の後継選択を実装する。固定砲台も作戦参加可能とし、指揮役と隊列の先頭役を分離する。
巡回・追撃と引き付けて攻撃の設定・段階を扱う。具体的な作戦例に依存せず、リーダーが判断して指示を出せる構成にする。一斉射撃の例について追加の仕様決定は必要としない。
先に共有情報の更新規則、指揮可能の判定、同順位・後継不在時の扱い、停止距離の扱いを決める。
検証: 状態遷移、情報共有、作戦の攻撃保留と解除、個別射撃条件、リーダー交代後の状態継続、固定砲台の指揮、未所属の互換性、再発見、停止距離の往復防止、通常待機が行動不能にならないこと。

段階1の最初の実装として、Manifestの任意グループ定義と、独立したリーダー選出・継承処理を追加した。保存・読み込みの互換性と不正参照、交代後のリーダー維持をヘッドレス試験で検証する。次の変更で配置・ゲーム内更新へ接続し、探知の共有、観測位置・時刻の保持、実際の撃破によるリーダー継承を追加した。さらに任意のpatrol設定に基づく行動制御を接続し、巡回・接近・停止・捜索・待機から目標と攻撃要求を生成する。実際の走行・射撃要求の適用・作戦・経路・隊列への接続は未実装。

## 段階2: 固定地形の経路と簡易移動

多層格子、走行面間の接続、車体寸法による通行判定、所要時間を評価する経路探索を実装する。
地形ごとのコストで経路上を簡易移動する。巡回・接近・記録位置移動で共用し、目標の移動・経路なしに対する再探索を加える。
リーダーが移動メンバー全員の通行条件で共有経路を計算し、一列の順番・車間を守って追従する。後続の遅れで先頭が減速・待機し、接敵中も隊列を維持する。個別の地形速度補正と局所回避を分離する。部隊分割・横隊は対象外とする。
検証: 異なる車体・地形適性の共有経路、固定砲台の通行条件除外、経路探索の共有、一列追従と接敵停止、舗装路と湿地の所要時間比較、地形境界の通過、車体幅・頭上空間・水深制限、橋の上下分離、ランプ接続、経路なし。

段階2の最初の実装として、多層格子の明示接続による時間最小経路、全移動メンバーの通行条件、地形境界を考慮した簡易移動、走行性能のJSON保存・読み込みを追加した。小さな格子のヘッドレス試験で検証する。走行面JSONの保存・読み込みと、巡回目標のセル対応付けを追加し、設定済みのグループで経路と停止理由を参照できるようにした。マップフォルダからの自動読み込み、明示した格子での敵走行、接近・捜索目標の走行面特定を接続した。格子生成、隊列、動的地形変更に応じた再探索は未実装。敵の表示は当面自機モデルを共用し、性能の入力は将来の自機・敵共通定義につなぐ。

## 段階3: 履帯物理との切り替え

複数敵のTankController利用に必要な管理変更は、独立したリファクタリングとして先に行う。
距離による物理・簡易移動の切り替えと、位置・姿勢・速度・走行面・行動・攻撃状態の引き継ぎを実装する。
切り替え距離に差を設け、近い敵は遮蔽中も物理で更新する。走行面を考慮して接地位置を決定する。
検証: 近距離の遮蔽、境界での連続切り替え防止、橋の上下の保持、姿勢・速度引き継ぎ、衝突体の二重生成防止と解放。
GUI確認を行う場合はDocs/renderer-development.mdを先に読む。

## 段階4: 占有・予約と復帰

現在位置の占有と進行先の予約を分離し、狭路の優先通行・後続待機・再探索を実装する。
進展のない移動と通常待機を区別し、行動不能が継続した場合の復帰を実装する。
復帰候補は配置ごとに優先順で保存し、安全性と移動元・先の不可視継続を確認する。HP維持、姿勢・速度リセットを行い、単独なら巡回、所属メンバーなら最後尾への合流を行う。
行動不能メンバーは一定時間待って隊列から外し、本隊を続行する。リーダーの離脱時は指揮を引き継ぎ、復帰後も現リーダーを維持する。合流用の個別経路がなければ待機・再探索する。
検証: 離脱後の本隊続行、合流用探索と最後尾への復帰、リーダー離脱・復帰後の指揮維持、対向・後続・停止時の占有、残骸、予約解放、HP維持、候補全滅時の待機、画面内では復帰しないこと、復帰直前の条件変化。

## 段階5: 動的な地形と構造物

影響範囲付きの変更通知から走行面・接続を部分更新し、該当経路と予約を再確認する。
地形変形、湿地化、浸水・排水、倒壊中の危険区域、倒壊後の瓦礫、橋の崩落に対応する。
足場を失った遠距離敵は物理へ切り替える。安定して通行可能な面へ対応付けられれば簡易移動へ戻し、走行不能なら停止・復帰へつなげる。
変形・水・倒壊の生成側は別途範囲を決め、まず再現可能な変更入力で経路側を検証する。
検証: 変更範囲外の経路維持、上下両面への崩落影響、画面外の変更、足場崩壊時の落下、安定後の復帰、更新と物理の整合。

## 各段階の完了条件

- 対象範囲の意味のあるヘッドレス試験が成功する。
- 既存の固定砲台・戦闘・自機走行の関連試験が成功し、プロジェクトがビルドできる。
- 設定の保存・ロード、旧JSONの互換性、不正値の拒否を検証する。
- 実装した範囲と未実装の範囲を資料へ反映する。

負荷目標、敵数、更新頻度は未決定。性能測定に基づく最適化は機能検証後に行う。

## 簡易巡回の実行接続

マップフォルダの任意ファイル navigation.json をロードし、走行面 grid と drivers を指定する。driver は groupId、enemyId、surfaceId、snapDistanceMeters、mobility を持つ。現段階は1グループ1台の移動に限定し、固定砲台が指揮する場合も移動車両の位置で経路を計算する。巡回の全区間と周回の戻りをロード時に検証する。スナップ距離は到達半径以下とする。

地形コストに応じた位置をキネマティックな敵ボディへ適用する。巡回の到達判定は通過済みノードで行い、区間途中で経路を切り替えない。破壊時は移動を停止し、マップ再初期化時に設定を再適用する。固定砲台は設定しなければ移動しない。

移動車両はマイタンクと共通のメッシュ・材質を使い、位置と向きは個別に反映する。車輪・履帯は敵自身の状態で表示し、表示設定はマイタンクと共通とする。衝突形状は既存砲台の代理形状であり、隊列、追跡先の走行面解決、動的地形更新は後続の実装である。

## 近距離履帯物理の初期接続

移動車両はマイタンクとの3次元距離30m以下で専用TankControllerへ切り替える。位置・回転・線速度とHPを引き継ぎ、遮蔽の有無は切り替えに使用しない。経路上の次ノードへ向く基本操舵と前進・停止を入力する。旋回入力、前進量、ノード到達の詳細チューニングは初期値段階である。

40m以上で簡易移動への復帰を試みる。接地、垂直速度の安定、車体の直立、既知の経路ノードへの対応が確認できなければ物理を継続する。復帰後は現在位置から経路を再計算する。追跡先の走行面を接地点と明示した高さから解決し、対応不能の場合は移動を停止する。

Enemy Unit Editor に物理への切り替え距離と簡易移動への復帰距離を追加。変更は次の物理ステップから適用され、リセットは不要。敵タイプJSONの simulation に保存し、旧JSONは30m/40mを使用する。復帰距離は切り替え距離より大きくなければロード・適用を拒否する。表示LODはこの距離設定と独立している。敵の車輪・履帯表示は敵自身の足回りスナップショットを参照する。

現段階の物理衝突はTankControllerの車体箱を使い、表示砲塔には独立した当たり判定を持たない。命中試験は車体を通る射線で検証する。復帰は位置対応と安定条件を優先し、40mを超えても対応不能なら物理を継続する。旋回中の経路からの逸脱・減速調整は引き続き必要。

## 物理巡回の旋回・減速

EnemyTrackedSteering は目標方向と速度から左右履帯の入力を生成する。大きな方向転換では前進を止めて旋回し、真後ろ付近では直前の旋回方向を維持する。Joltの履帯0が車体+X側にあることに合わせて入力する。減速は移動プロフィールの速度上限、残り距離、設定した制動減速度を目安とする。到達半径に入るまでは前進を維持し、入ったら制動する。ノードの完了は到達半径内かつ水平速度0.25m/s未満で判定する。

制動減速度（初期2m/s2）と経路ノード到達半径（初期0.5m）をEnemy Unit Editorからプレイ中に変更でき、simulationのJSONに保存する。旧JSONの省略値はこの初期値を使う。平地の巡回往復と行き過ぎ上限をヘッドレス統合試験で検証する。荒地・傾斜・湿地の物理移動での調整は今後の検証対象である。

## 敵ごとの足回り表示

PhysicsはEnemyRunningGearStateとして車輪の姿勢・接地と左右履帯の角速度を公開する。Renderingはメッシュを共有したまま、近距離敵の車輪姿勢、接地色、履帯経路、左右別の履帯移動位相を更新する。描画更新だけでは位相を進めず、物理時間を使用する。

簡易移動への切り替えで物理スナップショットを解除し、戦車設定に基づく標準足回りと敵の前進速度を使う。各敵の履帯位相はモード切り替えをまたいで保持する。マイタンクや別の敵の運動をコピーしない。車輪・履帯の表示切り替えと破壊時の非表示も適用する。glTFの一体化された車体・側面メッシュ自体は従来どおり剛体表示であり、サスペンションと履帯運動は既存の車輪・履帯インスタンスで表現する。

## 観測した目標の走行面と追跡

各走行セルに任意の supportHeightMeters を追加する。これは物理地形の接地高さであり、車体中心用の position.y と分ける。プレイヤーの上向き接地法線を持つ車輪のうち、支持力が最大の接地点を使用し、水平範囲と高さ許容差で候補セルを照合する。別の面が同距離で重なる場合、接地がない場合、明示高さがない場合、範囲外の場合は対応不能として停止する。上下の面をつなぐ経路リンクは別途明示し、観測だけで接続を生成しない。傾斜面は明示した平面勾配で高さを補間する。格子生成は未実装。

実際の観測位置はグループ情報に残し、攻撃距離判定に使用する。経路計算には対応セルの車体中心位置とsurfaceIdを使い、見失った後の捜索にも最後に観測した対応を引き継ぐ。移動中と攻撃距離で停止中も、最後に到達した走行セルを経路の起点として保持する。これにより目標更新時の区間途中の対応失敗と、停止から捜索へ移る際の起点喪失を防ぐ。

Enemy Unit Editorで観測目標の対応半径（初期6m）と接地高さの許容差（初期0.2m）をプレイ中に変更でき、敵タイプJSONへ保存する。旧navigation.jsonは巡回互換を保つが、追跡のためにはsupportHeightMetersの明示が必要となる。

## 傾斜した接地面の対応

セルに任意の supportGradientXZ: [dx, dz] を追加する。各値は世界X/Z方向に1m進んだ場合の接地高さの増分で、正負の両方を許容する。supportHeightMetersはセルpositionのXZでの基準接地高さであり、車輪の実際の接地点XZで height = base + dx * offsetX + dz * offsetZ を計算する。観測位置と接地点の両方が対応半径内にある場合だけ照合する。例として [0, 0.25] はZ方向へ4m進むと1m上る平面となる。

車体中心と車輪接地点の位置がずれる坂道にも対応し、橋の上下は同じ高さ照合と曖昧時の停止ルールを維持する。勾配から求めた傾斜角も通行判定へ含め、既存slopeDegreesとの大きい方を使う。勾配の省略値は [0, 0] で旧JSONを水平面として維持する。非ゼロ勾配には基準接地高さを必須とし、配列の形・数値・有限性を検証する。曲面、段差の境界、走行面の自動生成は後続となる。

## ユーザテスト用コース

Assets/Map/EnemyMovementTestを追加。3台の移動戦車、灰色の巡回直線、中央の追跡・射撃車両と遮蔽壁、青い橋と上り下りの坂道を用意する。走行格子と配置、敵タイプはマップフォルダ内に保存する。scripts/run-enemy-movement-test.batはbuild-working2/Releaseの最新アプリでマップを直接読み込む。詳しい順序と制限はマップ内README.mdを参照する。

Enemy Unit EditorのEnemy movement statusで、各敵の物理/簡易モード、距離、HP、グループ行動、目標走行面、経路停止理由を確認できる。自動試験では実際のglTF当たり判定と全巡回経路、遠距離巡回、近距離物理、追跡・射撃、坂道登坂を検証する。描画付き自動起動とスクリーンショットの保存も確認する。ユーザによる操作感・切り替えの違和感の評価はこれから行う。

## 簡易移動での超信地旋回

移動方向へ姿勢を即時変更する処理を廃止する。次の経路ノードの方向へ、位置を固定して段階的に旋回し、向きがそろってから移動する。ノードを跨いだ残り時間で次区間へ進まないため、折り返しや角で向きの異なる区間へ流れ込まない。真後ろへの旋回方向は直前の方向を保持する。左右履帯の表示速度は車体の前進速度と旋回角速度から求め、旋回中は逆回転する。

Simple pivot speed（初期60度/秒）は敵調整UIからプレイ中に変更でき、敵タイプJSONのsimulation.simpleTurnDegreesPerSecondへ保存する。180度の折り返しは初期値で約3秒となる。近距離では既存の履帯物理による超信地旋回を使用する。
