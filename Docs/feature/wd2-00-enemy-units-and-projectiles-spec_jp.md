# WD2-00 敵ユニットと敵弾の開発仕様

更新日: 2026-10-04
状態: 初期仕様（実装完了を示すものではない）

## 目的

敵ユニットと敵弾を開発する。最初の敵ユニットは、移動しない固定砲台とする。
敵ユニットと敵弾は、それぞれ種類を追加できる構成を目指す。

## 固定砲台

- 移動しない。
- 耐久力を持ち、破壊可能とする。
- 耐久力・被弾・破壊の扱いは、現在の破壊可能オブジェクトから引き継ぐ。
- プレイヤーの Tank に対して敵弾を発射する。
- 砲台の耐久力の具体値、照準・射程・発射間隔は未確定。

## 敵弾

敵弾は複数タイプを扱う。現時点では次の2系統を定義する。

| 系統 | 迎撃による破壊 | 形状・大きさ |
| --- | --- | --- |
| 敵通常弾 | プレイヤー Tank の通常弾・迫撃砲で破壊可能 | 未確定 |
| 敵特殊弾 | 破壊不可 | さまざまな形状・大きさを持つ |

- どちらの系統も、自機 Tank に当たるとダメージを与える。
- 初期設定では、敵弾の接触ダメージを100とする。
- 敵通常弾を破壊するのに必要な命中数・耐久力は未確定。
- 敵特殊弾にプレイヤーの弾が当たった際、プレイヤーの弾が消えるか通過するかは未確定。
- 弾道、速度、寿命、地形との衝突、命中後の敵弾の扱いは未確定。

## 自機のHP・残機

オリジナルのゲームは1回の被弾で MISS となる残機制だが、本プロジェクトではHPを用いて同じ初期挙動を表現する。
本仕様では、自機のHPが0になって1機を失うことを Lost と呼ぶ。

| 項目 | 初期設定 |
| --- | --- |
| 最大HP | 100 |
| 開始時HP | 100 |
| 敵弾の接触ダメージ | 100 |
| 開始時残機 | 3 |

- HPが0になると Lost とし、残機を1減らす。
- 初期設定では1回の被弾で Lost となる。
- 開始時の残機3は、合計3回の Lost で GameOver になる数え方とする。
- HPとダメージは、後から調整できるようJSON設定で扱う。

## Lost・復帰・GameOver・Continue

| 遷移 | 残機 | HP | 位置 |
| --- | --- | --- | --- |
| ゲーム開始 | 3 | 100 | マップ開始位置 |
| 1回目の Lost 後の復帰 | 2 | 100 | 被弾した位置 |
| 2回目の Lost 後の復帰 | 1 | 100 | 被弾した位置 |
| 3回目の Lost | 0 | 0 | GameOver。通常の復帰は行わない |
| GameOver 後の Continue | 3 | 100 | マップ開始位置 |

- 残機がある場合、Lost 後は被弾した位置で復帰する。
- GameOver 後の Continue は、マップ開始位置へ戻り、残機3・HP100で再開する。
- 復帰までの時間、無敵時間、復帰時の姿勢・速度は未確定。
- Lost・Continue 時に敵ユニットや敵弾をリセットするかは未確定。
- GameOver・Continue の表示や操作方法は未確定。

## 実装上の制約

- 物理・戦闘処理を Rendering に依存させない。
- 自機との連携は TankController を中心とする既存構成に合わせる。
- 調整パラメーターはJSONで編集可能にする。
- 既存の破壊可能オブジェクトの挙動を維持し、小さな段階で実装・テストする。

## Type 0: 最初の固定砲台タイプ

Type 0として、移動しない固定砲台を定義する。以下は敵ユニット側のパラメーターであり、敵弾の通常弾・特殊弾という系統とは別に扱う。

| 記号 | パラメーター | 意味 |
| --- | --- | --- |
| a | 視界（探知）範囲 | 自機が範囲に入ると敵が自機を認識する |
| b | 射程範囲 | 探知範囲の内側にある |
| c | 射撃範囲 | 射程範囲の内側にある。自機を引きつけて射撃できるようにする |
| d | 弾速 | 発射する敵弾の移動速度 |
| e | 発射間隔 | 射撃の時間間隔 |

範囲は外側から探知範囲、射程範囲、射撃範囲の順とする。
射程範囲と射撃開始の範囲を区別し、射程に入っただけで直ちに射撃する仕様にはしない。

### 設定・配置・調整の開発順序

1. 最初は固定値でType 0を動作させる。
2. 次にJSON記述とロードに対応する。
3. 敵ユニットエディターでパラメーターを編集し、JSONへSaveできるようにする。
4. マップエディターで敵ユニットを配置する。
5. テストプレイしてパラメーターを調整する。

固定値の段階でも設定値のまとまりを用意し、後のJSON化・エディター保存へつなげる。
敵ユニットのタイプ定義と、マップ上の配置データを分ける。

### Type 0の未確定事項

- 範囲が円・球・扇形などのどの形状か。初期数値は後述の既定値を使用する。
- 探知時に地形による遮蔽を考慮するか。
- 探知範囲を出た場合の認識解除、射撃範囲を出た場合の射撃停止。
- 射程範囲を、弾の最大飛距離や寿命にも使用するか。
- 射撃範囲へ入った直後の初弾タイミング。
- 照準・砲台の向き・敵弾の弾道。

## Type 0追加: 砲塔旋回と射撃角度判定

| 記号 | パラメーター | 意味・単位 |
| --- | --- | --- |
| f | 砲塔の最大旋回速度 | 自機への照準方向へ旋回する速度の上限。度/秒 |
| g | 射撃可能な照準角度の閾値 | 現在の砲塔方向と自機への照準方向との角度誤差の許容値。±度 |

- 自機の移動に対して照準方向を瞬時に一致させず、砲塔の最大旋回速度を制限して照準の遅れを表現する。
- 射撃範囲の内側にいても、照準角度の誤差が±閾値以内になるまでは射撃しない。
- 射撃可能な角度になっても、発射間隔の条件を満たす必要がある。
- f・gも、固定値、JSONロード、敵ユニットエディターで編集・Saveの順に対応する。
- 水平旋回のみか上下照準も含むか、閾値の境界値を含めるかは未確定。f・gの初期値は後述の既定値を使用する。
- 別の待機時間としての照準遅延は、現時点では確定仕様に含めない。最大旋回速度による追従の遅れを扱う。
## 攻撃タイプと複数砲台の設定: 2026-10-04

- 移動データとは別に攻撃タイプを登録・調整する。
- 敵タイプの各砲台（攻撃場所）へ攻撃タイプを割り当てる。
- 1体に複数砲台を持たせられるよう、砲台ごとの位置と攻撃タイプ参照を保持する。
- GUIで攻撃タイプと敵タイプを登録し、各砲台へ割り当てられるようにする。

| パラメーター | Type 0の既定値 |
| --- | --- |
| a 探知範囲 | 50 m（障害物なしの平地） |
| b 射程範囲 | 30 m |
| c 射撃範囲 | 25 m |
| d 弾速 | 1 m/秒 |
| e 発射間隔 | 3秒 |
| f 最大砲塔旋回速度 | 5度/秒 |
| g 射撃角度閾値 | ±3度 |

調整の目安は戦車約10台分で50 m、現在のカメラでは前後約5台分の25 mで画面外。
遮蔽、範囲形状、認識解除、初弾の扱いは引き続き未確定。
