# 迫撃・ローリング入力／状態遷移 仕様草案

## 1. 目的

左右2本のアナログレバーから通常走行、迫撃姿勢、左右ローリングを一貫して判定し、入力競合を防ぐ。

本仕様はゲーム操作と状態遷移を定める。Jolt Physicsによる姿勢制御、弾道、ダメージ計算の詳細は別仕様とする。

### 1.1 座標系契約

本プロジェクトのゲーム座標系はDirectX 12の左手系とする。モデルローカル座標系とワールド座標系は同じ軸規約を使用する。

```text
+X: 右
+Y: 上
+Z: 前
```

- identity poseではモデル軸とワールド軸が一致する。
- RtPbrSurveyの上位レイヤ、Tank Physics、描画モデル、カメラ追従の間で、座標軸の入替え、符号反転、手系変換を行わない。
- 位置、方向vector、quaternionは同一の軸規約で受け渡す。境界ごとに暗黙のZ反転を加えてはならない。
- `yawRadians`はワールド`+Y`軸まわりの回転であり、yawが0の車体正面はワールド`+Z`である。

ローリングはモデルローカル`Z`軸まわりの回転である。左右レバーの共通符号を`RollSign`と定義する。

| レバー入力 | `RollSign` | 回転トルク |
|---|---:|---|
| `(-1, -1)` | `-1` | モデルローカル`Z`軸の負回転 |
| `(+1, +1)` | `+1` | モデルローカル`Z`軸の正回転 |

`RollSign`は、カメラ向き、ワールド上の見かけの左右、車体の表裏、前回のロール方向、Rolling状態により反転してはならない。横移動は独立に左右を固定せず、現在上を向く面がこの`Z`軸回転で倒れ込む接線方向へ必ず追従する。

## 2. 設計原則

- 入力認識と物理制御を分離する。
- 生のレバー値を直接 `TankController` の特殊挙動へ渡さない。
- 一度開始した特殊動作は、開始条件ではなく専用の継続・終了条件で管理する。
- 迫撃とローリングは同時に開始しない。
- 認識閾値と物理調整値はJSONから変更可能にする。
- 描画、カメラ、エフェクトは物理状態を参照するが、物理状態を決定しない。

### 2.1 状態遷移モデル

迫撃とローリングの制御には、明示的な階層型状態遷移モデルを使用する。入力条件や物理判定を複数の `if` 文へ分散させず、現在状態、イベント、ガード条件、遷移先、遷移時アクションとして定義する。

```text
SpecialMoveMachine
  Normal
  Mortar
    Raising
    Aiming
    MaxElevation
    Recoil
    Blocked
    Lowering
    Aborting
  Rolling
    Windup
    PoweredRoll
    Evaluating
    BallisticRoll
    Blocked
    RecoveringToStart
    Settling
    Aborting
  Recovering
```

上位状態は特殊動作間の排他制御を担当し、迫撃とローリングの下位状態は各動作の物理進行を担当する。

### 2.2 遷移の構成要素

各遷移は次の形式で定義する。

```text
Transition
  fromState
  event
  guard
  action
  toState
```

例:

| 現在状態 | イベント | ガード条件 | 遷移時アクション | 次状態 |
|---|---|---|---|---|
| Normal | MortarRequested | `MobilityState == Stopped`、必要接地あり | 迫撃基準姿勢を記録 | Mortar.Raising |
| Mortar.Raising | MinimumElevationReached | 姿勢が発射許容範囲内 | 発射許可、範囲表示開始 | Mortar.Aiming |
| Mortar.Raising | ProgressBlocked | 妨害確認時間を超過 | 妨害イベント生成、発射禁止 | Mortar.Blocked |
| Normal | RollRequested | `MobilityState == Stopped`、開始姿勢が安全 | 開始軸と位置を記録 | Rolling.Windup |
| Rolling.PoweredRoll | QuarterTurnReached | なし | 完了可能性を評価 | Rolling.Evaluating |
| Rolling.BallisticRoll | ProgressBlocked | 妨害確認時間を超過 | 妨害イベント生成 | Rolling.Blocked |
| Rolling.Blocked | RecoveryPlanned | 復帰経路が利用可能 | 回復出力を有効化 | Rolling.RecoveringToStart |

### 2.3 更新規則

- 状態遷移の評価は物理ステップごとに1回行う。
- 1物理ステップ内で通常は1遷移までとし、遷移連鎖による状態飛び越しを防ぐ。
- `OnEnter` で基準姿勢の記録、タイマー初期化、通知イベント生成などを行う。
- `OnUpdate` で力、トルク、進行度、妨害監視値を更新する。
- `OnExit` で当該状態だけが所有する制御出力やタイマーを解除する。
- 状態変更は状態機械だけが行い、UI、カメラ、武器システムから直接変更しない。
- 同じ入力列と同じ物理観測値に対して、同じ遷移結果を返す決定的な処理にする。

### 2.4 イベント分類

```text
InputEvent
  MortarRequested
  RollLeftRequested
  RollRightRequested
  SpecialInputReleased

PhysicsEvent
  MinimumElevationReached
  MaximumElevationReached
  QuarterTurnReached
  LandingDetected
  PoseSettled
  ProgressBlocked
  SafetyLimitExceeded

SystemEvent
  FireRequested
  RecoveryPlanned
  RecoveryFailed
  StateTimeout
```

入力イベントは要求であり、必ず遷移するとは限らない。ガード条件を満たさない場合は状態を維持し、開始拒否理由または妨害理由を出力する。

### 2.5 状態遷移の観測性

テストとデバッグのため、直近の遷移記録を読み取れるようにする。

```text
StateTransitionRecord
  stepIndex
  previousState
  event
  guardResult
  nextState
  reason
```

リリースビルドで履歴保存を無効化しても、現在状態、状態滞在時間、最後の遷移理由は取得可能にする。

### 2.6 走行・停止状態モデル

特殊動作とは独立した `MobilityStateMachine` を設け、車体が走行中か停止中かを物理観測値から判定する。

```text
MobilityState
  Moving
  StopCandidate
  Stopped

Moving
  └─ 停止候補条件成立 ─> StopCandidate

StopCandidate
  ├─ 条件を規定時間維持 ─> Stopped
  └─ 条件喪失 ─────────> Moving

Stopped
  ├─ 走行入力受理 ─────> Moving
  ├─ 速度閾値超過 ─────> Moving
  └─ 接地・安定条件喪失 > Moving
```

`Stopped` は単にアクセル入力がゼロ、またはブレーキ中であることを意味しない。次をすべて満たし、`stoppedConfirmSeconds` 継続した状態を停止とする。

- 車体の実並進速度が `stoppedEnterLinearSpeed` 以下。
- ヨー、ピッチ、ロールの実角速度が `stoppedEnterAngularSpeed` 以下。
- 横滑り、斜面での滑落、外力による押し流されが停止閾値以下。
- 履帯の過大な空転や接地点に対する相対滑りがない。
- 走行再開に必要な履帯接地と、許容範囲内の車体姿勢がある。
- 迫撃、ローリング、安全復帰の途中ではない。

惰性走行、スリップ、横滑り、斜面での滑落、衝突で押されている状態など、操作入力に対して制御しにくい運動もすべて `Moving` とする。プレイヤーが走行入力を放していても `Stopped` にはしない。

停止判定にはヒステリシスを持たせる。`Stopped` へ入る閾値より、`Moving` へ戻る閾値を少し高くし、境界付近で状態が往復しないようにする。ただし走行入力が受理された場合は、実速度がまだ低くても直ちに `Moving` へ戻す。

迫撃とローリングの開始条件には個別の「ほぼ静止」判定を持たせず、必ず `MobilityState == Stopped` を使用する。開始要求があっても `Moving` または `StopCandidate` なら拒否し、UI向けに `VehicleNotStopped` を返す。

## 3. 入力モデル

各レバーを2次元の正規化値として扱う。

```text
leftStick  = (leftX,  leftY)
rightStick = (rightX, rightY)

X: 左=-1、右=+1
Y: 後=-1、前=+1
```

入力処理は、次の論理入力を生成する。

```text
DriveInput
  leftTrack
  rightTrack

SpecialActionIntent
  None
  Mortar
  RollLeft
  RollRight
```

デッドゾーン適用後の入力を使い、特殊操作判定には走行入力より高い開始閾値を設ける。開始と解除で異なる閾値を使い、境界付近のチャタリングを防ぐ。

初期調整値:

| 項目 | 初期値 | 意味 |
|---|---:|---|
| stickDeadZone | 0.15 | 通常の入力デッドゾーン |
| specialEnterThreshold | 0.75 | 特殊操作の開始判定 |
| specialExitThreshold | 0.45 | 特殊操作の保持解除判定 |
| specialHoldSeconds | 0.12秒 | 誤入力防止の同時保持時間 |
| simultaneousWindowSeconds | 0.08秒 | 左右入力を同時操作とみなす時間差 |
| neutralRearmSeconds | 0.10秒 | 中断後や別の特殊操作を許可する中立時間 |

## 4. 特殊操作のジェスチャー

### 4.1 迫撃

左レバーを左、右レバーを右へ倒す。プレイヤーから見て、左右のレバーを外側へ開く操作を迫撃入力とする。

```text
左レバー  ←     →  右レバー
            外開き
```

```text
leftX  <= -specialEnterThreshold
rightX >= +specialEnterThreshold
```

逆方向の「左レバーを右、右レバーを左」という内側へ閉じる操作は、迫撃入力として扱わない。

両方が `specialHoldSeconds` 継続し、開始可能条件を満たした時点で `Mortar` を確定する。

迫撃姿勢は仰角0度から開始し、ウイリーの進行に合わせて仰角が自動的にゆっくり増加する。レバーの前後成分で仰角を直接操作しない。

- 迫撃中のレバー入力は姿勢開始・保持・解除の判定に使い、走行や旋回には使わない。
- 発射は専用の射撃ボタンで行う。外開き入力そのものでは発射しない。
- 最低発射仰角へ達するまでは発射できない。
- 最低発射仰角から最大仰角までは発射でき、仰角は自動的に増え続ける。
- 最大仰角へ達したら仰角の増加を停止し、その姿勢を保持する。

### 4.2 ローリング

暫定割り当てとして、左右レバーを同じ横方向へ倒す。

```text
左ローリング: leftX <= -threshold かつ rightX <= -threshold
右ローリング: leftX >= +threshold かつ rightX >= +threshold
```

この割り当ては実機『アサルト』の操作確認および通常旋回との操作感テスト後に確定する。入力認識層が `RollLeft` / `RollRight` を出力するため、物理側は割り当て変更の影響を受けない。

1回のローリングは独立した1回転として開始・完了判定する。ただし、ローリング終了時に左右レバーを再評価し、両方が同じ方向へ倒れたままなら、中立へ戻さなくても次のローリングを開始可能とする。

- ローリング中の入力保持によって、実行中の1回転へ追加トルクを無制限に加えない。
- 1回転が正常終了して姿勢と速度が開始可能条件へ戻った時点で、次の `RollLeft` または `RollRight` を判定する。
- 同方向入力が継続していれば、通常の保持時間をもう一度要求せず、次の1回転を開始できる。
- 入力が中立または左右不一致なら、ローリング連続起動を終了する。
- ローリングが障害物などで中断した場合は連続起動せず、一度中立へ戻すまで再受付しない。

## 5. 入力の優先順位と競合解決

通常状態での候補判定順は次の通りとする。

1. 迫撃の完全な外開き入力
2. 左右ローリングの同方向入力
3. 通常の履帯走行入力

ただし、優先順位だけで即決せず、特殊操作は保持時間を満たした時点で確定する。保持中は通常走行を急停止させず、入力を徐々に制限するか直前の走行指令を短時間保持する。特殊操作が不成立なら通常走行へ戻す。

特殊動作中は新しい特殊操作を受け付けない。終了後、原則として両レバーが中立域へ `neutralRearmSeconds` 戻るまで再受付しない。ただし、正常終了したローリングから次のローリングへ連続起動する場合だけは例外とし、終了時の同方向入力を新しいローリング要求として再評価する。

## 6. 上位状態機械

```text
Normal
  ├─ Mortar確定 ──────> Mortar
  ├─ RollLeft確定 ────> RollingLeft
  └─ RollRight確定 ───> RollingRight

Mortar
  └─ 終了 ────────────> Recovering ──> Normal

RollingLeft / RollingRight
  ├─ 完走＋同方向入力継続
  │      └────────────> Recovering ──> RollingLeft / RollingRight
  ├─ 完走＋入力不成立 ─> Recovering ──> Normal
  └─ 失敗／中断 ──────> Recovering ──> Normal
```

`Recovering` は通常走行へ戻す共通の上位状態である。内部では迫撃復帰とローリング安定化を別処理にしてよい。復帰完了まで履帯出力は制限する。

## 7. 迫撃の詳細状態

```text
Inactive
  └─ 開始受理 ─> Raising

Raising
  ├─ 最低発射仰角へ到達 ─> Aiming
  ├─ 入力解除 ─> Lowering
  └─ 進行妨害／安全条件喪失／時間切れ ─> Blocked

Aiming
  ├─ 仰角自動増加 ─> Aiming
  ├─ 最大仰角へ到達 ─> MaxElevation
  ├─ 発射許可＋射撃 ─> Recoil
  ├─ 入力解除 ─> Lowering
  └─ 安全条件喪失 ─> Aborting

MaxElevation
  ├─ 姿勢保持 ─> MaxElevation
  ├─ 発射許可＋射撃 ─> Recoil
  ├─ 入力解除 ─> Lowering
  └─ 安全条件喪失 ─> Aborting

Recoil
  ├─ 安定回復かつ最大仰角未満 ─> Aiming
  ├─ 安定回復かつ最大仰角 ─> MaxElevation
  ├─ 入力解除 ─> Lowering
  └─ 安全条件喪失 ─> Aborting

Blocked
  └─ 妨害サイン通知 ─> Aborting

Lowering / Aborting
  └─ 通常姿勢へ復帰 ─> Inactive
```

### 7.1 開始可能条件

初期案では次をすべて満たすこと。

- `MobilityState == Stopped`。
- ヨー、ピッチ、ロール角速度が上限以下。
- 後部を含む必要数の履帯接地点がある。
- 車体ロール角と地面傾斜が許容範囲内。
- 空中、転倒、ローリング中、復帰中ではない。
- 発射クールダウン中であっても姿勢移行は可能だが、発射は不可。

開始不可の場合は通常走行を維持し、UI向けに拒否理由を返す。

### 7.2 Raising

- 履帯の走行指令を抑制する。
- 仰角0度を迫撃開始時の基準とする。
- 後部接地を維持しながら車体前部を持ち上げ、仰角を0度から一定の低速で増加させる。
- 最低発射仰角へ達するまでは発射を禁止し、攻撃範囲サークルを表示しない。
- 最低発射仰角へ達したら `Aiming` へ進み、発射を許可する。
- `mortarRaiseTimeoutSeconds` を超えたら `Blocked` へ進む。

ウイリー制御中は、要求している上昇と実際の仰角進行を比較する。次のいずれかが `mortarBlockedConfirmSeconds` 継続した場合、物理的要因でウイリーが妨げられたと判定する。

- 姿勢制御出力が上限付近なのに、仰角の増加速度が最低値を下回る。
- 車体前方または上方で、進行を妨げる接触反力が閾値を超える。
- 必要な後部接地を失い、目標姿勢へ安全に移行できない。
- 横滑り、ロール傾斜、意図しない移動が許容範囲を超える。

単一フレームの衝突や路面の細かな凹凸だけでは妨害扱いにしない。妨害確定時は発射を禁止し、理由を通知して、安全復帰へ移る。

### 7.3 Aiming

- 仰角を `mortarElevationRateDegreesPerSecond` でゆっくり増加させ続ける。
- 仰角は `[mortarMinFireElevation, mortarMaxElevation]` の範囲に制限する。
- 最大仰角へ達したら `MaxElevation` へ進み、その角度で停止・保持する。
- 実車体角から弾道と予想着弾点を計算する。
- 最低発射仰角から最大仰角まで、予想着弾点を中心とする攻撃範囲サークルを地面に表示する。
- 仰角上昇に合わせて予想着弾点とサークルを連続的かつ単調に遠方へ移動させる。
- サークル半径は爆発範囲を表し、仰角によって爆発半径が変わらないなら一定とする。
- 目標角との差、角速度、必要な接地状態が許容範囲内のときだけ発射可能とする。
- 発射時は通常弾の4倍を基準威力とする範囲攻撃を生成し、`Recoil` へ進む。

表示サークルは予測結果であり、発射時には実際の弾道と衝突結果を正とする。地形、障害物、車体の揺れによって予想着弾点が変化した場合は毎フレーム更新する。

一定初速の単純な放物運動では、最大射程となる角度を越えると仰角を増やしても射程が短くなる。この仕様では攻撃範囲が遠方へ移動し続けることを優先し、最大仰角を射程増加区間内に制限するか、仰角から希望射程を求めて弾道初速を調整する。

### 7.4 迫撃中のカメラ

ウイリーの進行に合わせてカメラを動かし、遠方へ移動する攻撃範囲サークルをプレイヤーが確認できるようにする。これは任意の演出ではなく、迫撃の照準操作を成立させるための機能要件である。

- カメラ変化の目的は、迫撃の予想着弾点と攻撃範囲を画面内へ収めることである。
- 発射可能な状態では、予想着弾点と攻撃範囲サークルを照準判断に十分な大きさで視認できなければならない。
- 攻撃範囲が画面外にあり狙えない状態は、カメラ機能が未成立であり、迫撃操作の完成とはみなさない。
- 仰角0度から最低発射仰角、最大仰角へ進むにつれて、カメラも連続的かつ急激な飛びのない形で変化させる。
- カメラは `MortarState` の進行度、実仰角、予想着弾点、攻撃半径を参照する。
- カメラの照準視界制御から車体姿勢、迫撃状態、弾道結果を変更しない。
- 迫撃終了時は通常カメラへ滑らかに復帰させる。
- 現在存在する3つのカメラモードそれぞれで、位置、注視点、距離、画角をどう変化させるかは、迫撃実装が進むまで保留する。
- 迫撃中にカメラモード切り替えを許可するか、および切り替え時の補間方法も同時に決定する。

初期実装ではカメラの具体的な動作を固定せず、各カメラモードが迫撃表示へ対応できる共通入力情報だけを定義する。

### 7.5 解除と異常終了

- 外開き入力のどちらかが解除閾値を下回り、解除猶予を超えたら `Lowering`。
- 転倒方向への過大角度、接地喪失、強い衝突では `Aborting`。
- `Lowering` は制御された復帰、`Aborting` は安全を優先して姿勢制御出力を制限する復帰とする。

## 8. ローリングの詳細状態

```text
Inactive
  └─ 左右開始受理 ─> Windup

Windup
  ├─ 起動条件成立 ─> PoweredRoll
  └─ 条件喪失／時間切れ ─> Aborting

PoweredRoll
  ├─ 90度へ到達 ─> Evaluating
  └─ 進行妨害／異常検出 ─> Blocked

Evaluating
  ├─ 完了可能 ─> BallisticRoll
  └─ 完了困難 ─> Blocked

BallisticRoll
  ├─ 着地検出 ─> Settling
  └─ 進行妨害／時間切れ ─> Blocked

Settling
  ├─ 姿勢・速度安定 ─> Inactive
  └─ 時間切れ ─> Aborting

Blocked
  └─ 妨害サイン通知 ─> RecoveringToStart

RecoveringToStart
  ├─ 開始姿勢へ安全復帰 ─> Settling
  └─ 復帰不能／安全上限到達 ─> Aborting

Aborting
  └─ 安定または停止 ─> Inactive
```

### 8.1 開始可能条件

- 車体が接地している。
- `MobilityState == Stopped`。
- ロール角、ピッチ角、角速度が許容範囲内。
- 迫撃、別のローリング、復帰、重大な衝突状態ではない。

ローリングはタンクが `Stopped` の場合だけ開始できる。開始前の空間検査だけで完走可否を決定せず、障害物との実際の接触を物理シミュレーションへ反映する。

### 8.2 ローリング動作

- 開始時の前方、上方、重心位置、ロール方向を固定して記録する。
- `PoweredRoll` では車体前方軸まわりのトルクを加える。
- 最初の90度までは起動フェーズとして回転を進める。
- 90度へ達した時点で、障害物との接触、回転速度、必要トルク、横移動の進行量から、残りの回転を物理的に完了可能か判定する。
- 完了可能なら回転を継続し、完了困難なら無理なトルクや位置補正を加えず `Blocked` へ移る。
- 0度から90度まで、および90度から180度までの全区間で、回転角速度、回転進行量、接触反力、制御出力を監視する。
- 90度地点の評価後であっても、マップ形状への引っ掛かりや新しい衝突を検出したら `Blocked` へ移る。
- 横移動制御は目標距離を持つが、障害物へ押し込み続けないよう接触時に制限する。
- 着地後は角速度を減衰させ、正立または裏返りの近い側へ安定化する。
- 物理的には1回ごとに回転を完了させ、終了時の入力再評価で次の1回転を起動する。
- 同方向入力を保持している間は、中立復帰なしでローリングを繰り返せる。
- 次の回転も `MobilityState == Stopped` などの開始可能条件を満たしてから開始する。入力保持だけを理由に安全条件を省略しない。

途中で中断した場合は瞬間的に正立へ戻さない。物理挙動を保ちながら、原則として回転してきた方向を逆にたどり、開始姿勢側への復帰を補助する。

- 回復トルクと横移動力には通常ローリングより低い上限を設ける。
- 障害物へ押し込み続けず、接触反力が上限を超えたら出力を弱める。
- 急激な角速度を抑え、車体または履帯の接地を回復しながら戻す。
- 元の姿勢へ安全に戻れない場合は強制回転や座標補正を行わず、横倒しなど現在の物理結果を許容する。
- 復帰中は連続ローリングを禁止し、復帰後も一度中立へ戻すまで再受付しない。

### 8.3 ローリング中の当たり判定

ローリングでは、車体の姿勢変化に追従して衝突形状も回転する。約90度では正面または背面から見た被弾領域が縦長かつ横に細くなるため、敵弾を回避する操作として利用できる。

- 被弾判定専用に一時的な縮小や無敵化を行わない。
- 物理用車体形状とゲーム用被弾形状を分ける場合も、両方を車体姿勢へ追従させる。
- 履帯、砲塔、車体など部位別形状を採用する場合は、見た目と被弾結果が一致する構成にする。
- ローリング中も通常どおり敵弾との連続衝突判定を行い、高速な姿勢変化による弾抜けを防ぐ。

回避性能は90度付近の投影面積が小さくなることから自然に生じるものとし、追加の回避率や確率判定は設けない。

### 8.4 成功と失敗

成功条件:

- 規定の回転進行を完了する。
- 接地後、姿勢誤差と角速度が規定時間内に閾値以下になる。

失敗条件:

- 側面障害物への強い衝突。
- 90度地点の継続判定で、障害物、回転速度不足、過大な抵抗などにより完了困難と判断される。
- 回転または横移動が一定時間以上停滞。
- 車体姿勢または角速度が安全範囲を超える。

失敗時に姿勢を瞬間補正しない。制御を弱め、通常の物理結果を許容しつつ、まず `RecoveringToStart` で開始姿勢側への復帰を補助する。安全に復帰できない場合だけ `Aborting` へ移る。

### 8.5 妨害判定

ローリング開始から着地まで、次の状態が `rollBlockedConfirmSeconds` 継続した場合に進行妨害を確定する。

- 駆動または回復トルクが上限付近なのに、回転角の進行が最低値を下回る。
- 横移動が停滞し、進行方向の接触反力が閾値を超える。
- 車体、砲塔、履帯などがマップ形状へ継続して接触し、回転を妨げている。
- 回転軸が大きく崩れ、残りの回転を安全に制御できない。

0～90度と90～180度で別々に監視値を記録し、どの区間で妨害されたかを通知情報へ含める。瞬間的な接触だけで誤判定しない一方、強い衝突が安全閾値を超えた場合は確認時間を待たず即時に妨害を確定できる。

## 9. 妨害サイン

ウイリーまたはローリングの妨害を確定したフレームで、物理側は一度だけ `SpecialMoveBlocked` イベントを生成する。UI、サウンド、ゲームパッド振動などはこのイベントを参照して、プレイヤーへ失敗と復帰開始を伝える。

最低限必要なサイン:

- 画面上で短時間確認できる共通の妨害表示。
- 迫撃では攻撃範囲サークルを無効表示に切り替え、発射不能を示す。
- ローリングでは復帰方向が決まったことを視覚的または音で示す。
- 妨害理由が解消せず復帰不能の場合は、通常の妨害表示とは区別できるサインを出す。

具体的なアイコン、色、効果音、振動パターンは表示仕様で決定する。`TankController` は表示を直接行わず、次の理由コードと物理状態を返す。

```text
SpecialMoveBlockReason
  ProgressStalled
  ObstacleContact
  ExcessiveContactForce
  RequiredContactLost
  RotationAxisLost
  RecoveryFailed
```

### 10.1 デバッグダイアログの状態表示

デバッグダイアログの最上部に状態サマリーを常時表示する。調整パラメーターより上へ配置し、折りたたみ項目の中には入れない。ダイアログ内の設定項目をスクロールしても状態サマリーを確認できる構成にする。

最低限、次を表示する。

```text
Mobility: Stopped
Special:  Mortar / Raising
Input:    MortarRequested
Status:   Active
Reason:   None
```

- `Mobility` は `Moving`、`StopCandidate`、`Stopped` を省略せず表示する。
- `Special` は上位モードと下位フェーズを併記する。
- 特殊操作の認識中は入力候補と保持進行度を表示する。
- 開始拒否時は `VehicleNotStopped` などの拒否理由を表示する。
- 妨害時は `Blocked`、妨害区間、`SpecialMoveBlockReason` を表示する。
- 安全復帰中は復帰先と復帰進行度を表示する。
- 状態滞在時間と直近の遷移理由を表示できるようにする。
- 色分けを使用してもよいが、色だけに依存せず必ず状態名を文字で表示する。
- 正常、候補、実行中、妨害、復帰失敗を視覚的に区別する。

表示は読み取り専用とし、デバッグUIから状態を直接書き換えない。状態変更の試験操作が必要な場合は、通常の状態遷移イベントを発生させる専用テスト操作として別に設ける。

## 11. 責務境界案

```text
Input Adapter
  生デバイス入力、デッドゾーン、左右レバー値
        ↓
Special Action Recognizer
  ジェスチャー、保持時間、ラッチ、再受付
        ↓
Special Move State Machine
  状態、イベント、ガード、遷移アクション、失敗復帰
        ↓
TankController
  Jolt観測値の提供、力・トルク・履帯指令
        ↓
Gameplay Weapon System
  発射、弾道、通常弾4倍の基準威力、範囲ダメージ
        ↓
Camera Aiming Support
  迫撃進行度と予想着弾範囲を参照した照準視界制御
```

状態機械はJolt固有型を持たず、正規化した物理観測値を受け取って状態と制御要求を返す。`TankController` は状態機械の要求を上限付きのJolt制御へ変換する。

`TankController` はダメージ対象、描画、カメラを知らない。武器システムは `MortarState::canFire` と発射姿勢を参照し、発射結果と反動要求を返す。カメラ側は読み取り専用の迫撃状態と弾道予測を参照し、物理や武器状態へ指令を返さない。

## 12. 最低限のテスト

入力認識の単体テスト:

- 外開きが保持時間未満なら迫撃を開始しない。
- 外開きが成立すると迫撃だけを1回開始する。
- 同方向入力が成立すると指定方向のローリングだけを開始する。
- 特殊動作中は別の特殊入力を無視する。
- ローリング正常終了時に同方向入力が継続していれば、中立復帰なしで次のローリングを要求する。
- ローリング正常終了時に入力が中立または左右不一致なら、連続起動しない。
- ローリング失敗または中断後は、入力を保持していても連続起動せず、中立復帰を要求する。
- 連続ローリングでも各回の開始可能条件を評価する。
- 閾値付近のノイズで状態が往復しない。

状態遷移モデルの単体テスト:

- 各状態について、許可されたイベントだけが定義された遷移を起こす。
- ガード条件が偽なら状態を維持し、制御開始アクションを実行しない。
- 1物理ステップで複数状態を意図せず飛び越えない。
- `OnEnter` と `OnExit` が遷移ごとに1回だけ実行される。
- 妨害イベントが継続しても `SpecialMoveBlocked` を1回だけ生成する。
- 同じ入力イベント列と物理観測値列から同じ状態遷移記録を生成する。

走行・停止状態の単体テスト:

- 入力がゼロでも惰性速度が残っていれば `Moving` を維持する。
- 並進速度が低くても旋回中、横滑り中、履帯空転中なら `Stopped` にしない。
- 停止候補条件が確認時間未満なら `StopCandidate` を維持する。
- 停止候補条件を規定時間維持した場合だけ `Stopped` へ移る。
- `Stopped` で走行入力を受理したら、実速度が上がる前に `Moving` へ移る。
- 停止閾値付近のノイズで `Moving` と `Stopped` を往復しない。
- `Moving` または `StopCandidate` では迫撃とローリングの開始を拒否する。

デバッグ表示の確認項目:

- ダイアログを開いている間、状態サマリーが最上部に常時表示される。
- `Moving -> StopCandidate -> Stopped` の変化が次の更新で表示へ反映される。
- 迫撃・ローリングの上位状態と下位フェーズが一致して表示される。
- 開始拒否、妨害、安全復帰、復帰失敗の理由が文字で表示される。
- 設定項目をスクロールしても状態サマリーが隠れない。

物理状態遷移テスト:

- 平地静止から `Raising -> Aiming -> Lowering` を完了する。
- `Stopped` 以外では迫撃とローリングを開始しない。
- 迫撃は仰角0度から開始し、最低発射仰角より前では発射できない。
- 最低発射仰角で発射可能になり、攻撃範囲サークルを表示する。
- 仰角と予想着弾点が徐々に増加し、最大仰角で停止する。
- 迫撃進行中にカメラ向けの仰角進行度と予想着弾範囲が連続して更新される。
- 発射可能な全仰角で、予想着弾点と攻撃範囲サークルが照準可能な状態で画面内に収まる。
- 迫撃終了時にカメラ復帰状態が通知される。
- 迫撃中の接地喪失で `Aborting` へ移る。
- ウイリーの進行が一定時間停滞したら妨害を確定し、理由を一度だけ通知する。
- 瞬間的な接触や小さな路面変化ではウイリー妨害を誤通知しない。
- ウイリー妨害後は発射を禁止し、上限付き制御で通常姿勢へ復帰する。
- 左右ローリングが規定方向へ開始し、90度で完了可否を評価する。
- 障害物がない場合は90度地点からローリングを継続する。
- 障害物で完了困難な場合は過大な力を加えず `Blocked` へ移り、妨害を通知して安全復帰を試みる。
- 0～90度で引っ掛かった場合に妨害を通知し、開始姿勢側へ復帰を試みる。
- 90～180度で新たに引っ掛かった場合も妨害を通知し、開始姿勢側へ復帰を試みる。
- 復帰経路も塞がれている場合は、強制姿勢補正せず `RecoveryFailed` を通知する。
- 90度付近で被弾形状が車体姿勢に追従し、横方向の投影幅が正立時より狭くなる。
- ローリング完了後に有限値を保ち、安定状態へ到達する。
- 不正な設定値やゼロ `deltaTime` でNaNを生成しない。

## 13. 未決事項

- ローリングの正式なレバージェスチャー。実機準拠を優先するか、現代的な操作性を優先するか。
- `Stopped` の進入・離脱速度、角速度、履帯滑り量、確認時間。
- 迫撃の仰角増加速度、最低発射仰角、最大仰角。
- 攻撃範囲サークルを遮蔽物の手前に置くか、遮蔽物越しの地形着弾点に置くか。
- 3つのカメラモードごとの迫撃中の位置、注視点、距離、画角、補間方法。
- 迫撃中のカメラモード切り替えを許可するか。
- 妨害サインのアイコン、色、効果音、振動パターン。
- ローリングが90度を越えた後、開始姿勢へ戻るより回転完了の方が安全な場合の回復経路選択。
- 外開き入力を解除した時点で直ちに復帰するか、迫撃モードをトグル保持するか。
- ローリング中の衝突ダメージ、無敵時間、攻撃判定。
- 裏返りでローリングを完了した場合を成功として扱うか。
- 迫撃の「通常弾4倍」を直撃値、爆心値、範囲全体のいずれに適用するか。

## 14. 推奨する最初の実装範囲

1. 描画や武器に依存しない `SpecialActionRecognizer` と入力テスト。
2. Jolt固有型に依存しない `SpecialMoveStateMachine` と遷移テスト。
3. 既存 `roll` 入力を `RollLeftRequested` / `RollRightRequested` イベントへ置き換える境界。
4. 迫撃の物理処理をまだ行わない状態遷移テスト。
5. 平地限定の `Raising -> Aiming -> Lowering` 物理実験。
6. 既存ローリング試作を詳細状態へ分割し、障害時の終了条件を追加する。

この順序なら、入力仕様を先に固定し、迫撃とローリングの物理調整を独立して小さく進められる。
