# 敵移動の開発仕様

更新日: 2026-10-11
状態: 合意した仮仕様。実装完了を示すものではない。

## 目的と境界

敵戦車の移動を、近距離では履帯物理、遠距離では地形コストによる簡易計算で扱う。表示は近距離の履帯付きモデルと遠距離の簡略モデルをLODで切り替える。表示LODと移動計算LODは独立して扱う。
物理・行動・経路探索はRenderingに依存させない。近距離の走行はTankControllerを中心とする構成に合わせ、調整値はJSONで編集可能にする。
現在の配置処理は固定砲台を生成し、EnemyUnitTypeには移動設定がない。本仕様はその拡張であり、既存固定砲台の挙動を維持する。

## 行動

| 状態 | 行動 |
| --- | --- |
| 通常 | 配置ごとに指定された経路を巡回 |
| 自機を発見 | 自機へ接近 |
| 攻撃距離に到達 | 停止し、射撃可能なら射撃 |
| 自機を見失う | 最後に見た位置へ移動 |
| 記録位置に到着 | 一定時間待機。再発見したら接近へ戻る |
| 待機終了 | 再発見できなければ巡回へ戻る |

射撃は既存攻撃タイプの射撃範囲、照準角度、発射間隔、探知状態を満たす場合に行う。停止後、条件が整うまでは照準を続ける。
停止距離と再接近距離には差を設け、境界での発進・停止の繰り返しを抑える。移動タイプと攻撃タイプは独立させる。

## グループ指揮と情報共有

マップでグループID、所属ユニット、指揮優先順位、初期作戦、巡回経路、隊列を設定する。同じ敵タイプでも配置ごとに別グループへ所属できる。固定砲台と移動ユニットを混在でき、未所属の敵は単独行動する。
グループ内で自機の発見情報を共有し、リーダーが作戦と移動を統括する設計案とする。リーダーの仕組みを用意した上で、経路計算の集約や作戦指揮に有効かを検証し、役割は縮小・変更できるものとする。共有情報、作戦の進行段階、経路・隊列情報はグループ側に保持し、リーダー交代でも継続する。
リーダーが破壊されたら、指揮可能な生存メンバーから設定された優先順位で後継を選ぶ。固定砲台も作戦指揮を引き継げる。作戦の指揮役と、実際に隊列の先頭を走る役は分離する。
共有情報は移動・作戦判断に使用する。各砲台の射撃可否は個別に判定し、共有情報だけで遮蔽物越しに射撃しない。

## グループ作戦

初期候補は「巡回・追撃」と「引き付けて攻撃」とする。

| 作戦 | 設定・動作 |
| --- | --- |
| 巡回・追撃 | 巡回経路、攻撃停止距離、見失った後の待機時間を使い、既定の行動遷移を統括 |
| 引き付けて攻撃 | 交戦区域、攻撃開始条件、参加ユニットを設定。リーダーが条件成立まで射撃を保留し、成立時に攻撃開始を指示 |

固定砲台も情報共有と作戦射撃に参加する。移動ユニットは作戦に応じて移動する。グループの攻撃指示と個別の射撃条件の両方を満たした場合に射撃する。
「引き付けて一斉射撃」は、リーダー判断を使う作戦の可能性を示す一例であり、実装必須の作戦や仕様決定項目ではない。

## 共有経路と隊列

リーダーが移動メンバー全員の通行条件を満たす経路を探索し、移動コストを計算する。固定砲台は通行条件から除外する。全員が通れる経路がなければ停止・再探索し、部隊分割は後続機能とする。
メンバーは共有経路へ隊列で追従し、通常の全体経路探索を人数分繰り返さない。各車両の足元の地形による速度補正、局所的な障害物回避、近距離の履帯物理は個別に処理する。追従できない場合だけ局所的な再探索を行う。
初期の隊列は一列とし、順番と車間距離を設定可能にする。先行車が通った経路を追従し、後続が遅れたら先頭が減速・待機する。横隊などは後続機能とする。
接敵時も隊列を維持する。各ユニットが攻撃停止距離に達するか、先行車との車間を守る必要がある場合に停止する。停止後は作戦の攻撃指示と個別射撃条件に従う。

## 隊列からの離脱と再合流

行動不能のメンバーを一定時間待ち、解消しなければ隊列から一時的に外して残りで続行する。外れたユニットは既定の行動不能からの復帰処理へ進む。
復帰後は、現在の隊列へ個別に合流用経路を探索し、最後尾へ合流する。合流中も地形・占有・予約と移動計算LODの規則を守る。経路が見つからなければ安全な場所で待機・再探索し、本隊は行動を続ける。
リーダーが行動不能で隊列から外れた時点で、指揮優先順位に従って後継へ指揮を渡す。復帰後も現リーダーを維持し、元のリーダーへ自動的には戻さない。

## 移動計算LOD

| 条件 | 計算 |
| --- | --- |
| マイタンクの近距離 | 遮蔽に関係なく履帯物理 |
| マイタンクの遠距離 | 見えるかに関係なく地形コストによる簡易移動 |
| 足場が崩壊 | 遠距離でも一時的に物理へ切り替える |

切り替えはマイタンクとの距離を基準とする。物理へ入る距離と簡易移動へ戻る距離に差を設ける。位置・向き・速度・走行面・行動・攻撃状態を引き継ぐ。
遠距離の簡易速度は「基準速度 ÷ 地形コスト」を基本とし、地形をまたぐ区間ごとに所要時間を計算する。通行不能は独立した条件とする。近距離の実測速度を使ってコストを調整する。
崩壊後は、車体が安定し、通行可能な走行面へ対応付けられた遠距離の敵を簡易移動へ戻す。落下・横転・瓦礫による不安定状態では物理を続ける。安定しても走行不能なら停止し、行動不能の復帰処理へつなげる。

## 多層格子と経路探索

同じ平面位置に複数の走行面を保持する多層格子を使う。各走行面は識別子、高さ・勾配、地形区分、水深、頭上の空間、障害物の占有、危険状態を持つ。
橋の上と下は別の走行面とし、平面位置が同じでも直接接続しない。坂道・ランプなど実際に移動可能な場所で接続する。敵と目標地点は位置だけでなく走行面を保持する。
車体幅・高さ、最大登坂角、通行可能な水深・段差から通行可否を判定する。狭い隙間や頭上空間不足を考慮する。
巡回・接近・記録位置への移動に共通の経路探索を使う。経路は距離だけでなく予想所要時間で選ぶ。近距離は物理で経路へ追従し、遠距離は簡易計算で同じ経路を進む。
目標が設定距離動いたら再探索する。経路が見つからなければ停止して一定間隔で再探索する。

## 動的なマップ変化

クレーター・隆起、舗装破損・湿地化、浸水・排水、建物や橋の倒壊、瓦礫に対応する。
地形・水・建物の変更を影響範囲付きで通知し、その範囲と車体幅に必要な周辺の走行面・接続を更新する。全面再構築を通常の更新方法にしない。
物理の衝突地形と経路データが同じ変更を受け取る。画面外の変化も経路に反映する。
倒壊中は危険区域として進入を避け、倒壊後は瓦礫の形状から通行可否とコストを再判定する。橋の崩落は上側の走行面・接続を無効化し、下側にも危険区域・瓦礫を反映する。
変更された範囲を通る経路を再確認する。通行不能なら停止して再探索し、コストだけの変更は一定間隔で経路を見直す。

## 敵同士の進路調整

車体サイズに応じた現在位置のセル占有と、狭路への進入予約を使う。橋の上下は独立して扱う。
先に進入した敵を優先し、後続は車間を空けて待機する。対向で通れない場合は片方が待機・再探索する。
停止中も現在位置の占有は維持し、不要な進行先の予約だけ解除する。破壊後の残骸は障害物として扱う。復帰・経路変更・地形変化では関連予約を更新または解除する。
通常の渋滞待ちは直ちに行動不能としない。長時間進展がなければ再探索し、解消しない場合に復帰処理へ進める。

## 行動不能からの復帰

横転、走行不能な場所への落下、移動意図があるのに進めない状態が一定時間続いたら、回復・再探索を試みた後、復帰地点へ戻す。
攻撃停止や通常の待機は対象外。破壊された敵の再出現は別ルールとする。
配置ごとに複数の復帰候補を優先順で指定し、初期配置地点も候補にできる。各候補には位置と走行面を指定する。
倒壊・浸水・他車両の占有などを安全確認し、使えなければ別候補へ進む。すべて使えなければ待機する。
移動元と復帰先の両方が、画面外または遮蔽によって一定時間見えない場合だけ復帰する。遠方でも画面に映っていれば待機する。復帰直前に安全性と可視状態を再確認する。
復帰時はHPを維持し、姿勢・速度をリセットする。単独の敵は巡回を再開し、グループ所属の移動メンバーは最後尾への再合流を行う。

## 段階1の最初の実装: グループ定義と指揮継承

2026-10-10時点で、Manifestの任意フィールドenemyGroupsと、独立したEnemyGroupCommandを追加した。配置とゲーム内のグループ更新・共有観測へ接続した。作戦と経路・隊列走行は未実装。

```json
"enemyGroups": [
  {
    "id": "patrol-001",
    "members": [
      { "enemyId": "enemy-001", "commandPriority": 10 },
      { "enemyId": "enemy-002", "commandPriority": 20 }
    ]
  }
]
```

enemyIdは敵配置のIDを参照する。グループは空にできず、同じ敵の複数所属を拒否する。commandPriorityは非負整数で、小さいほど優先する。同順位の選択規則を仮定しないよう、現段階ではグループ内の重複順位を拒否する。グループIDもマップ内の他のIDと重複できない。
旧マップはenemyGroupsなしで読み込み可能で、敵は未所属となる。保存・読み込み失敗時は既存データを保持する。
EnemyGroupCommandは外部から渡された指揮可否で現在リーダーを維持・交代する。指揮可能な候補がなければリーダーIDは空になり、候補が復帰すれば選出できる。指揮可否のゲーム内判定と、指揮不在中の作戦動作は後続で決定する。
現リーダーが指揮可能な間は、優先順位の高い元リーダーが復帰しても交代しない。

### 敵更新への接続

SpawnManifestEnemiesはマップの参照・所属を生成前に検証し、配置後にConfigureEnemyGroupsでグループを構成する。旧マップはグループなしで動作する。
各更新では、破壊されていない敵を指揮候補とし、リーダーを維持または継承する。現段階の対象は固定砲台で、行動不能・隊列離脱による指揮可否の変更は後続機能とする。
グループ内の生存メンバーのいずれかの砲台が現在自機を探知していれば、共有のdetectedを立て、最後に観測した位置と時刻を保存する。同じ更新の観測は同じ自機位置を対象とする。
全員が見失うか自機がLostになったらdetectedを解除し、観測履歴は維持する。履歴の期限や作戦判断にはまだ使用しない。共有情報を砲台の射撃判定へ入力しないため、見失った砲台が共有情報だけで射撃することはない。
観測時刻は自機の復帰でリセットされるTankControllerの時刻とは別に保持する。ワールドの再初期化ではグループと履歴を消去し、再配置で初期優先順位から選出する。
状態はTrackedVehicleTestState.enemyGroupsから参照できる。GUIのグループ編集・表示は未実装。
検証対象は、配置前の不正参照拒否、優先順位による初期選出、メンバーからの観測共有、実際の撃破による継承、全員が見失った際の履歴保持、遮蔽時の射撃禁止、再初期化と旧マップ互換性、自機復帰をまたぐ観測時刻。

## 段階1: 行動目標の生成

EnemyGroupBehaviorは巡回、接近、攻撃停止、記録位置の捜索、捜索待機、巡回復帰を判断する。移動目標と攻撃要求を出力し、実際の走行・射撃はまだ接続しない。固定砲台の位置や射撃挙動は変更しない。
グループの任意フィールドpatrolで以下をすべて明示した場合だけ有効にする。数値の既定値は決定せず、設定なしの旧グループには行動制御を追加しない。

- points: 巡回地点の配列。各地点にpositionとsurfaceIdを指定する。
- attackStopMeters: 正の攻撃停止距離。
- resumeApproachMeters: 攻撃停止距離より大きい再接近距離。
- arrivalMeters: 正の到着許容距離。
- searchWaitSeconds: 記録位置到着後の待機時間。0なら即巡回へ戻る。

再接近距離の境界に達すると再接近する。見失った後は未観測の自機位置を追わず、最後の観測位置を目標にする。待機中の再発見は待機を中断する。巡回復帰は中断時の巡回インデックスへ戻る。
グループ内の行動状態はリーダー交代でも維持する。指揮不在や自機Lost中はHold要求を出して状態と待機時間を停止する。
現段階の距離・到着判定は3次元の直線距離を使い、ゲーム内ではリーダー位置を判断の基準としている。固定砲台リーダーと移動部隊の先頭を分離する際には基準位置の入力を差し替える。
巡回目標の走行面IDは保持するが、到着時の走行面一致判定や、観測位置の走行面特定は経路層との接続時に追加する。到着待機時間は到着を検出した更新では減らさず、次の更新から減らす。
TrackedVehicleTestState.enemyGroupsのbehaviorで行動・目標・待機残時間・攻撃要求を確認できる。攻撃要求は射撃許可そのものではなく、現在は既存射撃へ入力していない。

## 段階2の最初の実装: 多層経路と簡易移動

NavigationGridとSimpleNavigationMovementを追加した。RenderingやJoltの車体に依存しない計算モジュールであり、現段階ではゲーム内の敵位置・モデル・衝突体へ接続していない。
格子セルはx・z・surfaceIdの組で識別し、位置・地形・幅と頭上空間・勾配・水深・通行可否を持つ。異なる走行面は同じ平面セルに共存できる。隣接セルの明示的な有向接続だけを探索し、上下の自動接続や斜めの自動通過は行わない。
接続にも通路幅・頭上空間・段差を指定する。セルの勾配だけでなく、接続両端の高低差による勾配も確認する。セル幅と接続は、車体の通過範囲を考慮して作成する必要があり、実地形からの生成処理は未実装。
NavigationMobilityには基準速度・車体幅と高さ・最大勾配・水深・段差・地形別コストを保持し、JSON保存と読み込みに対応した。road / ground / rough / marshのコストは正の値を必須とし、通行禁止はセルのpassableで扱う。現段階では実測に基づく既定値を設けない。
Dijkstra法で予想時間が最小の経路を求める。接続区間の前半を出発セル、後半を到着セルの地形として評価する。グループでは移動メンバー全員の通行条件を満たし、各半区間で最も遅いメンバーの速度を採用する保守的な時間評価とする。固定砲台は呼び出し側が移動メンバーから除外する。
SimpleNavigationMovementは各メンバーの性能で同じ経路を進む。地形境界・接続終点ごとに残り時間を消費し、大きな更新間隔でも途中の移動コストを飛ばさない。位置と高さを接続に沿って補間し、最後に到達した走行面と次の走行面を保持する。
経路は格子のrevisionを記録した値のコピーとして返す。変更の影響判定と再探索の呼び出しは後続実装とし、現在の移動処理が動的更新を自動検出するわけではない。探索・初期化失敗時は前の出力を保持するため、呼び出し側は失敗を検出して移動を停止する必要がある。
検証済みの範囲: 舗装への迂回、異なる車体幅と速度のグループ経路、橋の上下分離とランプ、水深・勾配・頭上空間・段差・通行禁止、時間刻みの一致、到着停止、不正入力、JSON往復。
未実装: マップからの格子生成・編集、開始位置と行動目標の走行面対応付け、ゲーム内の敵走行、隊列追従、再探索スケジューリング、物理LOD、動的地形。

## 戦車定義と表示の後続方針

敵戦車は当面、自機と同じモデル・履帯表示を共用する。個体の操作・位置・HPなどは独立して保持する。
戦車のモデル・車体物理・走行性能・武器搭載などの共通定義を、自機と敵の双方へ割り当てられる形へまとめる。敵専用の設定を二重に増やすことは避ける。NavigationMobilityも、この共通定義から供給できるよう操作主体に依存しない構成とした。
共通定義の交換はまず生成・再配置時を想定し、走行中の交換は別途検討する。敵戦車エディタは共通定義を編集する後続機能とし、現在は未実装。

## 段階2: 走行面JSONと行動目標の接続

SerializeNavigationGrid / DeserializeNavigationGridで走行面と有向接続をJSONに保存・読み込みできるようにした。versionは1。cellsにはx、z、surfaceId、position、terrain、clearanceWidthMeters、clearanceHeightMeters、slopeDegrees、waterDepthMeters、passableを指定する。linksにはfrom / toのセル配列インデックス、clearanceWidthMeters、clearanceHeightMeters、stepMetersを指定する。
revisionは動的更新用の実行時情報で、JSONへ保存しない。読み込み失敗時は以前の格子を維持する。
EnemyNavigationPlannerはグループの移動目標と開始位置を、指定走行面の最寄りセルへ対応付ける。許容距離は呼び出し側が明示し、同距離の候補、走行面不明、範囲外なら停止して経路を解除する。橋の下など別の面へ勝手に補完しない。
開始セル・目標セルが同じ間は経路または探索失敗の結果を再利用する。格子や移動性能の変更はConfigureで再設定して探索をやり直す。失敗時の定期再探索・動的変更通知は後続機能とする。
TrackedVehicleTest::ConfigureGroupNavigationで格子、移動メンバーの性能、対応付け許容距離、判断基準の走行面を設定できる。設定されたグループは各更新で行動目標を経路へ変換し、enemyGroupsのnavigationから経路・停止理由・探索回数を参照できる。
現段階の基準位置はリーダー位置で、固定砲台と移動部隊の先頭の分離は未実装。固定砲台を含む実配置ではまだ移動を適用しない。性能リストのメンバー対応付けも呼び出し側の責任とする。
巡回の目標にはsurfaceIdがあるため経路化できる。接近・捜索は観測位置の走行面が未特定なので停止する。射撃要求が出て移動目標がなくなった場合も経路を解除する。
検証: JSON往復・不正接続拒否、巡回目標から経路生成、同じ経路の再利用、経路を使った簡易移動の到着、走行面不明時の停止、ゲーム内の巡回要求からの経路参照。
未実装: マップフォルダからの走行面ファイルの自動読み込み・グループへの設定、地形からの格子生成、観測走行面の特定、敵車体への移動適用、画面上の敵戦車表示。現段階ではロード用APIと実行時の接続を用意し、既存マップには設定を追加していない。
